# Design system and product screens
The current visual authority is [DESIGN.md](../DESIGN.md), with machine-readable extensions in [.impeccable/design.json](../.impeccable/design.json). The user selected near-black and purple gradients, warm off-white/beige and visible 3D executives; this replaces the prior emerald direction for Next.js and React/Vite. Studio Sans is self-hosted Manrope under the OFL, not a new external font request. Existing Vite compatibility token names may retain “emerald” while their values are purple.

The executive studio presents real Three.js geometry, a separate owner approval station and recorded task handoffs. Next/React 19 and Vite/React 18 share the framework-neutral model and renderer inside `frontend/src/studio`; keep this placement compatible with the frontend Docker context. Historical snapshots do not replay. Synthetic preview remains explicitly labelled and performs no task mutation. Owner authorization and CEO review remain separate. Optional immersive view retains a focus trap, Escape exit and opaque backdrop; optional camera follow stops under reduced motion. Preserve equivalent accessible team selection and task details outside the 3D view.

The following screen inventory is planned scope, not evidence of implemented screens. Existing controls should retain labels, visible keyboard focus, field errors and preserved input. Verify contrast and responsive behavior on actual combinations; this document does not certify WCAG compliance or provider readiness.

Screens: landing; signup/login/reset/verification; onboarding; company settings; member roles; integration connect/status; goals/plans; command center; five department workspaces; task list/detail; approvals; calendar; inbox; candidate pipeline; campaigns/assets; budget/ledger; knowledge upload/search/source inspection; CEO brief; notifications; audit history; usage/billing configuration.
Task detail includes origin, owner, deadline/timezone, prerequisites, version, requested authority, cost, exact proposed external action, review history, execution attempts and completion evidence. Approval card names who requested it, what changes externally, whom it affects and who can decide. Preview content before approval. Separate “approved”, “sent”, “delivered” and “completed”.
Every screen specifies loading, empty, validation failure, disconnected integration, expired session, denied permission, partial success, retry and offline state. Optimistic UI is limited to reversible local edits; payments, publication and approval await authoritative response. Socket events invalidate query cache; persisted API state wins after reconnect.

The public landing has a scoped glass extension in `DESIGN.md` and `extensions.publicLanding` in `.impeccable/design.json`. Its dark/light palettes, stronger caption/dialog glass, self-hosted type and responsive player do not replace the authenticated boardroom system. Next and Vite share `LandingExperience.jsx` and the Three.js renderer, with mirrored landing CSS for their separate PostCSS pipelines. A visitor-started English speech-synthesis tour introduces the five departments with captions; voice availability depends on the OS/browser. Theme follows the OS until a persisted localStorage override and updates browser theme-color. The live 3D introduction is not prerecorded video and performs no task writes or external actions.

The shared five-role workflow (27 November) reuses the existing appearance tokens for readable conversation, bounded evidence, exact-version review and image-job states. It is shared React source in `frontend/src/workflow`, with mirrored CSS in `web/components/workflow.css` to preserve both build pipelines. Primary roles now include Strategy; legacy HR remains reachable. Voice transcripts require explicit Send. Stop/typed fallback, semantic headings/labels/status alerts and reduced-motion behavior remain available. No billing feature or screenshot assets were copied from the owner's references.
