# Six practical RAG improvements
The user named five techniques; the sixth is evaluation and freshness management.

1. Smart chunking: parse headings/paragraphs and document types; preserve tables and parent sections. Start experiments around 400–800 tokens with limited overlap, then tune from retrieval failures. Keep CVs, policies and financial tables in separate retrieval contexts. OCR only when needed; quarantine failed extraction.
2. Metadata and access: tenant, department, document ID/version, source, heading/page, author, uploaded_at, effective dates, confidentiality, consent/retention and checksum. Filter permissions before retrieval/reranking, never after returning snippets. Propagate deletion to lexical/vector indexes, caches and parent documents.
3. Hybrid search: combine lexical BM25 and dense embedding retrieval, merge using reciprocal-rank fusion. Start with roughly 20 candidates from each as a tuning hypothesis. Small FYP BM25 index may be rebuilt from authorized corpus; production index must support tenant filters and updates. Chroma alone does not imply full hybrid search.
4. Reranking: rerank merged authorized candidates with a local sentence-transformers CrossEncoder; feed only the strongest 4–8 chunks within budget. Benchmark latency and usefulness; provide fallback when reranker unavailable. Pin model identity/version and verify license before deployment.
5. Strict grounded prompt: treat retrieved text as untrusted evidence; answer only supported facts, cite document/version/page, distinguish policy from historical decisions, disclose conflict and abstain when evidence is insufficient. Never execute instructions from documents. Live money, deadlines and task status come from authoritative tools, not stale vector memories.
6. Evaluation and freshness: create at least 50 labelled representative queries across departments, exact terms, paraphrases, conflicting/outdated documents, missing answers and adversarial/tenant-isolation cases. Hold out evaluation questions. Measure Recall@k, ranking quality, citation correctness, groundedness, abstention, latency and cost. Compare each improvement against the same baseline. Re-index changed documents with checksums/versioning and atomic activation; retain ability to rollback an embedding/index version.

Ingestion: upload → scan/type validation → extraction → human-visible parse status → metadata/ACL → chunks → embeddings + lexical index → evaluation → activate. Retrieval traces store IDs/scores with sensitive content redacted. Candidate CV information must never leak into general Marketing retrieval.
Fine-tuning is deferred: first fix retrieval, tools and evaluation. Later consider it only for measured repeated style/structured-output failures with licensed consented training data and held-out comparison. Fine-tuning does not provide current company facts or tool authorization.
