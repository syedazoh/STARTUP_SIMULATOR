# Design system and product screens
Proposed continuation of Emerald, Champagne and Lavender direction. Use deep emerald for navigation/primary action, champagne for warm surfaces, lavender for agent/secondary highlights. Define semantic success/warning/error/info tokens separately; verify WCAG contrast on actual combinations before release. Inter/system font stack, 4px spacing base, consistent 8/12/16/24/32 spacing, restrained shadows and readable tables.
Choose shadcn/ui with selected Radix primitives; no parallel Chakra/MUI system. All forms need labels, help, keyboard focus, field errors and preserved input. Minimum comfortable touch targets, reduced motion, screen-reader live status and responsive navigation. 3D boardroom has equivalent accessible task list and can be disabled on slow devices.

Screens: landing; signup/login/reset/verification; onboarding; company settings; member roles; integration connect/status; goals/plans; command center; five department workspaces; task list/detail; approvals; calendar; inbox; candidate pipeline; campaigns/assets; budget/ledger; knowledge upload/search/source inspection; CEO brief; notifications; audit history; usage/billing configuration.
Task detail includes origin, owner, deadline/timezone, prerequisites, version, requested authority, cost, exact proposed external action, review history, execution attempts and completion evidence. Approval card names who requested it, what changes externally, whom it affects and who can decide. Preview content before approval. Separate “approved”, “sent”, “delivered” and “completed”.
Every screen specifies loading, empty, validation failure, disconnected integration, expired session, denied permission, partial success, retry and offline state. Optimistic UI is limited to reversible local edits; payments, publication and approval await authoritative response. Socket events invalidate query cache; persisted API state wins after reconnect.
